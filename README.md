### IMPORTANT RULES

- The main branch is `main`. All feature branches made during development will be merged into this.
- If two or more groups of people are working on different features, then please DO NOT COMMIT TO MAIN and commit to a `feat/your-feature-name` branch instead so that we can merge it properly.
- Using AI for the code is okay. However, when using an agent, please make sure that the files and directories stay organized (appropriate directory and file naming; SEE BELOW).
- Prefer squash commits while merging unless the changes must be preserved.

### CODEBASE CONVENTIONS

- To keep the codebase easy to sift through during final analysis and report generation, please maintain a separate `experiments` directory that has folders inside it detailing the name of the experiment and when it was run. Most importantly, these subfolders should contain copies of the original files and all outputs generated by the program must be contained in these subfolders. **If there are any hyperparameters, please keep them in the file or a .cfg/.yaml and NOT in the global env so that they are accessible to everyone.** If the input source for the program is variable (changing data), then make sure that that is saved here as well. If the data is unchanging, then it needn't be saved here as it leads to unnecessary duplication.
- Part of the reason why there are separate experiments subfolders is because running the experiments often involves changing lots of files. To reiterate, please keep all changes during experimentation confined to that subfolder and **refrain from filling normal codebase directories with AI-slop instruction or result files**. Note that AI code is completely fine as long as it's organized appropriately.

##### Example `experiments/` layout

```
experiments/

│   ├── run_eval.py                            # the script as it was run

```
